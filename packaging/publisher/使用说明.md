# ØchreCL 发布助手

新版需要同时选择：

1. `OchreCL-update.jar`。
2. 同一次构建提供的完整源码文件夹或 `OchreCL-source.zip`。

填写新版本号和更新说明，点击“本地打包并预检”。助手会先核对 JAR 内记录的源码和构建配置摘要，再准备本地源码提交，重打包并检查四个平台的安装包。预检不会上传或修改远程内容。公开源码仓库必须处于 main 分支且没有未提交修改；不会覆盖你的未提交工作。

核对预检结果后，点击“发布更新并同步官网”。发布包含完整源码 ZIP、更新 JAR、四种安装包和 SHA-256 校验文件，版本标签指向本次准备的源码提交。JAR 和源码不匹配、缺少源码校验记录、已有版本指向其他源码或附件摘要不一致时会停止，不会覆盖已公开的版本。

旧版本 JAR 没有源码校验记录时，需要重新构建再使用此助手。不要把不同构建生成的源码 ZIP 和 JAR 混在一起。

助手使用本机已登录的 GitHub CLI；不要填写或粘贴密码、令牌。完整安装包沿用本机已验证的运行环境模板，Java 或原生依赖发生变化时应先更新模板并实测。预检核对的是构建输入记录，不代替实际运行测试。

每次操作结束后可关闭助手。若刚更换了助手版本，先退出旧窗口，再重新打开。

## 发布后清理

默认勾选“发布成功后清理本地四平台安装包”。只有远程发布及附件摘要核对通过、官网提交也成功推送后，助手才删除该次打包目录中的两个 macOS DMG、Windows ZIP 和 Linux TAR.GZ。取消勾选即可保留它们。

update.jar、完整源码 ZIP、SHA256SUMS.txt、发布记录以及运行环境模板会保留。预检或发布失败时不执行这项清理。清理不会删除 GitHub 上的附件，也不会扫描或删除旧目录。已经清理的版本不能复用本地完整包缓存；下次发布请使用新版本号。
