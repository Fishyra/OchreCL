# beta 0.2 开发记录与“操作游戏”设计

本轮为开发测试构建，尚非新的公开稳定发行版。修改位于 launcher-dev/hmcl-source；不自动推送官网或 GitHub。

## 本轮实现

- 下载列表使用 JFXListView/JFXListCell 的虚拟化、选择与滚动；附加项项目行复用 TwoLineListItem、分类色块和 RipplerContainer。保留社区核心的图文卡片。
- 附加项搜索/详情、服务器构建选择复用 SpinnerPane；失败退出加载状态并提供重试。
- 游戏安装进度使用 Øchre 主题、标题图标、任务卡片；可切换静默模式，悬浮按钮变下载图标并播放一次扩散波纹。快速重开需等待旧弹窗关闭动画完成。
- 部署进度增加阶段说明、真实百分比、日志卡片和完成/失败图标；后台任务可从浮动任务菜单恢复。
- 浮动按钮右键展开矩形任务列表，可跳转安装、游戏运行面板、服务器控制台；列表独立滚动。
- 首次启动提供 ØchreCL 独立项目说明、主题色选择和简短动画导览；不会自动同意 Minecraft EULA。
- 游戏运行后提供停止/操作两个按钮。操作面板包含真实负载、日志、截图目录、日志目录、实例目录和明确确认的停止操作。
- 状态卡与资源卡根据可用宽度在 1×4 和 2×2 之间布局。
- 服务器自动放大前保存正常启动偏好；系统窗口因主题重建时转移临时状态；关闭时保留正常尺寸。
- 游戏/服务器/工具通过独立小型 JVM 管理 stdin 与持久日志，启动器退出后继续运行；下次启动核对 PID、启动时间、私有回环认证后重新接管，避免误认复用 PID。游戏控制台最大保留 32MiB 文件、界面保留最近 1200 行/18万字；历史服务端日志仍在游戏自己的 logs 目录。后台进程管理器限制 64MiB 堆。
- OpenFrp/SFTP 工具同样可恢复控制；工具输出保持丢弃策略以免保存认证信息，短期凭据文件由独立进程在工具退出时清理。
- 网络检测检查本机监听与状态响应，可启用连续异常告警并手动保存世界、暂停穿透。它不能确认 DDoS，也不能清洗上游网络洪泛；不会自动封禁玩家。监测、定时备份、计划重启目前仅在启动器开启期间工作。

## “操作游戏”布局

上方：实例名、运行状态与运行时长。
主体：1×4/2×2 负载卡片，下方实时日志，可复制负载/日志、跟随滚动。
底部：实例目录、截图目录、日志目录、停止游戏、关闭面板。

后续可扩展为运行/诊断/截图三个标签。诊断应基于明确证据（具体错误、Java 版本、缺失依赖），不能仅凭 CPU 高就自动给结论。跨平台切换游戏窗口、暂停单人世界、修改游戏内配置等需额外游戏侧通信能力，本轮不伪装为已实现。

## 必须保留的验证边界

- 旧版已经产生、没有进程描述文件的孤儿进程无法凭空恢复 stdin；这套恢复机制适用于本轮之后新启动的进程。旧进程应先从游戏/服务器自身正常退出。
- 微软登录尚无 Fishyra 的应用 ID/服务授权，不能宣布登录已修复；已加开发配置入口，见 OCHRE_MICROSOFT_LOGIN.md。
- 用户提及的图1/图2未随本条请求附上。实例设置先做窄窗口、Java 下拉框和长文本防溢出；网络按钮暂放服务器功能面板，待图片确认位置。
- 未运行 Whisky/Wine；Windows/Linux 原生重启、工具生命周期和视觉仍需对应系统验证。
- 不支持跨操作系统同时使用同一个运行目录；不同启动器副本应共用同一用户数据目录才能接管同一组进程。
